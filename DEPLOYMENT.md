# Deployment guide

The site is a static Vite build (`npm run build` → `dist/`). Because `vite.config.js` uses a
relative base (`./`), the same build works on every host below with no changes, including
GitHub Pages project URLs like `https://<user>.github.io/<repo>/`.

## How CI/CD is wired

| Workflow | File | Trigger | What it does |
|---|---|---|---|
| CI | `.github/workflows/ci.yml` | Pull requests, pushes to non-`main` branches | Installs, builds, uploads `dist` as an artifact |
| GitHub Pages | `deploy-github-pages.yml` | Push to `main` | Builds and publishes to GitHub Pages |
| Cloudflare Pages | `deploy-cloudflare.yml` | Push to `main` (opt-in) | Builds and deploys with Wrangler |
| Netlify | `deploy-netlify.yml` | Push to `main` (opt-in) | Builds and deploys with Netlify CLI |
| Vercel | `deploy-vercel.yml` | Push to `main` (opt-in) | Builds and deploys with Vercel CLI |

Opt-in workflows stay skipped until you set a repository **variable** (Settings → Secrets and
variables → Actions → Variables) such as `CLOUDFLARE_DEPLOY=true`. Pick one host, or run several.

Typical flow: work on a branch → open a pull request (CI builds it) → merge to `main` → deploys automatically.

## 1. GitHub Pages (simplest, free)

1. Push this project to a GitHub repository (default branch `main`).
2. Repo **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Push to `main` (or run the workflow manually from the Actions tab).
4. Site appears at `https://<user>.github.io/<repo>/`.

**Custom domain:** add the domain under Settings → Pages, create a `public/CNAME` file containing
just the domain (e.g. `anujavhanamane.com`), and add the DNS records GitHub shows you.

## 2. Cloudflare Pages

**Option A – GitHub Actions (this repo's workflow)**
1. Cloudflare dashboard → Workers & Pages → Create → Pages → *Direct Upload*; create a project (e.g. `anuja-portfolio`).
2. Create an API token (My Profile → API Tokens) with **Cloudflare Pages: Edit** permission. Copy your **Account ID** from the dashboard sidebar.
3. In GitHub → Settings → Secrets and variables → Actions:
   - Secrets: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`
   - Variables: `CLOUDFLARE_DEPLOY` = `true`, `CLOUDFLARE_PROJECT_NAME` = `anuja-portfolio`
4. Push to `main`. Live at `https://<project>.pages.dev`.

**Option B – Cloudflare's own Git integration (no workflow needed)**
Create a Pages project → Connect to Git → choose the repo. Build command `npm run build`,
output directory `dist`, environment variable `NODE_VERSION=22`.

Custom domains: project → Custom domains. The `public/_headers` file is applied automatically.

## 3. Netlify

**Option A – Git integration (easiest):** Add new site → Import from Git → pick the repo.
`netlify.toml` already sets the build command and publish directory.

**Option B – GitHub Actions:** create a site, then add secrets `NETLIFY_AUTH_TOKEN`
(User settings → Applications → Personal access tokens) and `NETLIFY_SITE_ID`
(Site configuration → Site ID), plus variable `NETLIFY_DEPLOY=true`.

## 4. Vercel

**Option A – Git integration (easiest):** Add New → Project → import the repo. `vercel.json` is detected.

**Option B – GitHub Actions:** run `npx vercel link` locally once; the generated
`.vercel/project.json` contains `orgId` and `projectId`. Add secrets `VERCEL_TOKEN`
(Account settings → Tokens), `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`, and variable `VERCEL_DEPLOY=true`.

## 5. Any other static host (Firebase, S3, Render, your own server…)

```bash
npm ci
npm run build
```

Upload the contents of `dist/`. No server-side rules are needed because the site is a single page.

---

## Using an absolute base path

Only needed if a host requires it:

```bash
VITE_BASE_PATH=/my-subpath/ npm run build
```

## Troubleshooting

- **Blank page on GitHub Pages:** make sure Pages source is set to *GitHub Actions*, not a branch.
- **Workflow skipped:** opt-in workflows need their `*_DEPLOY` variable set to `true` (a *variable*, not a secret).
- **`npm ci` fails:** commit `package-lock.json` (it is generated by `npm install`).
- **Thumbnails missing:** YouTube thumbnails need a real video link in `src/data/projects.js`, or use your own images in `public/images/`.
